# Прорыв плотины — визуализация зоны затопления

Интерактивная карта распространения волны прорыва по результатам расчёта
HEC-RAS 2D на ЦМР 5 м. Несколько сценариев, воспроизведение по времени,
отсчёт глубины под курсором. Работает как статический сайт — без сервера,
без тайлового бэкенда, без API-ключей.

## Почему так

GitHub Pages отдаёт только статику: TiTiler или GeoServer там не поднять.
Значит рендер должен происходить в браузере. Серия из десятков растров на
сценарий — это гигабайты float32, которые нельзя ни закоммитить, ни
загрузить в клиент.

Решение — сжать данные под задачу, а не под универсальность:

| шаг | что делает | эффект |
|---|---|---|
| обрезка | находит общий контур затопления по всем кадрам | убирает пустые поля растра |
| прореживание | 5 м → размер под экран (по умолчанию 1400 px) | 5–20× |
| квантование | float32 → uint8, 0 = сухо, 1..255 = глубина | 4× |
| атлас | кадры пакуются в PNG-листы 4096×4096 | 1 запрос на 20–30 кадров |

На демо-наборе: **~300 МБ исходных GeoTIFF → 3.6 МБ веб-ассетов**
(3 сценария × 48 кадров). Глубина сохраняется с шагом `maxDepth/255` —
для 17 м это 7 см, что тоньше погрешности самой модели.

В браузере кадры распаковываются в `Uint8Array`, соседние интерполируются
по времени и пишутся в `<canvas>`, который MapLibre проецирует на карту как
`canvas`-источник. Никакого WebGL-шейдера: 900×558 px укладываются в
~4 мс на кадр, а карта остаётся обычной картой — с зумом, масштабной
линейкой и атрибуцией.

## Быстрый старт

```bash
pip install -r requirements.txt

python scripts/make_demo_data.py     # синтетический прорыв, если своих данных нет
python scripts/prepare.py --clean    # сборка ассетов в web/data/

cd web && python -m http.server 8000
```

Открыть <http://localhost:8000>. Пробел — пуск/пауза, стрелки на шкале
времени — по кадру, перетаскивание гидрографа — перемотка.

> Открывать `index.html` двойным кликом нельзя: `fetch` манифеста
> заблокирует CORS. Нужен любой локальный сервер.

## Свои расчёты

Разложите экспорт RAS Mapper по каталогам — один каталог на сценарий,
один файл на временной шаг:

```
data/raw/
├── 01_polnyy-proryv/
│   ├── Depth (24JAN2024 06 00 00).tif
│   ├── Depth (24JAN2024 06 05 00).tif
│   └── ...
├── 02_chastichnyy-proryv/
└── 03_postepennyy-razmyv/
```

Имя каталога становится подписью сценария: числовой префикс задаёт порядок
и в подпись не попадает (`01_polnyy-proryv` → «polnyy-proryv»). Дата и время
берутся из имени файла — понимаются форматы RAS Mapper
(`24JAN2024 06 00 00`) и ISO (`2024-01-24T06-00-00`). Если распознать не
удалось, кадры нумеруются по порядку.

Требования к растрам: один канал, глубина в метрах, NoData на суше
(`-9999` или `NaN`). CRS любая — скрипт перепроецирует в EPSG:3857 сам.

```bash
python scripts/prepare.py --clean --max-dim 1600 --max-frames 80
```

- `--max-dim` — длинная сторона кадра в пикселях. Больше 1800 не имеет
  смысла: рендер начинает пропускать кадры на слабых машинах.
- `--max-frames` — если шагов больше, скрипт равномерно прореживает серию.

Порог «сухо/мокро» — константа `WET_THRESHOLD` в начале `prepare.py`,
по умолчанию 5 см.

## Что считается по дороге

Помимо кадров `prepare.py` кладёт в `web/data/`:

- `*_maxdepth.png` — огибающая максимальных глубин за весь период.
  Показывается кнопкой «Максимум».
- `*_arrival.png` — **время добегания**: индекс кадра, в котором пиксель
  залился впервые. В интерфейсе пока не используется, но посчитан и лежит
  в манифесте — это готовый третий слой, если карта пойдёт в реальную
  работу по ЧС.
- гидрограф площади затопления, средней и максимальной глубины по кадрам —
  это он рисуется в нижней полосе.

Площадь приводится к реальной: Меркатор растягивает её в `1/cos²φ`, на
широте 55° это ровно в три раза.

## Публикация

Ассеты (`web/data/`) коммитятся, исходные растры — нет: `data/` в
`.gitignore`. Пуш в `main` запускает workflow, который выкладывает `web/`
на Pages. В настройках репозитория нужно один раз выставить
**Settings → Pages → Source → GitHub Actions**.

Лимиты GitHub — 100 МБ на файл и мягкий 1 ГБ на репозиторий. При
разумных `--max-dim` уложиться легко. Если ассеты всё же перевалят за
сотню мегабайт, положите их в GitHub Releases или на Cloudflare R2 и
поменяйте базовый путь в `app.js` — формат читается по обычному HTTP.

## Известные ограничения

- Подложка — CARTO Dark Matter, публичный демо-эндпоинт. Для продакшена
  возьмите собственные тайлы или подписку.
- Между кадрами идёт линейная интерполяция глубины. Она сглаживает
  движение фронта, но это интерполяция, а не досчёт гидравлики: в момент
  прихода волны реальный фронт круче.
- Квантование обнуляет всё мельче `WET_THRESHOLD`. Для расчётов берите
  исходные GeoTIFF, эта карта — для чтения и показа.
- `make_demo_data.py` не является гидравлической моделью. Это кинематическая
  волна по синтетической долине, нужная только чтобы репозиторий собирался
  без реальных расчётов.

## Структура

```
scripts/prepare.py         пайплайн: GeoTIFF → PNG-атласы + manifest.json
scripts/make_demo_data.py  генератор синтетического набора
web/index.html             разметка
web/style.css              палитра и типографика
web/app.js                 распаковка, рендер, гидрограф, шкала
web/data/                  собранные ассеты (коммитятся)
data/raw/                  исходные растры (в .gitignore)
```
